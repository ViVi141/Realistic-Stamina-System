## 总评

**数学「骨架」清晰，但「文档 + 配置 + 孪生 + 环境新旧实现」四层系统性失配，整体评级 = 严重混乱（权威文档已不可作为代码一致性的可信参照）。**

- ✅ **单一事实来源**：`P(v)`（`SCR_RSS_MetabolismModel.CalculatePandolfPowerWatts` / `MetabolismPowerWatts`）、`invert(P)`（`MetabolismModel.InvertSpeedForPowerWatts`）、CP 动态链、W′ 放电均只有一处实现，其余模块为转发，无重复公式。
- ✅ **C↔Python 对齐区**：Pandolf（2.7/3.2/0.7/0.23/1.34）、ACSM（50/200/80）、LCDA 全组、CP 链（0.002/0.015/0.18）、Tobler 系数、`energy_to_stamina_coeff=9.5e-07` 兜底值，均一致。
- ❌ **根因**：缺少「文档 ↔ 代码 ↔ 烘焙预设 ↔ 孪生」四者的**单一真相源 + 自动对齐门禁**。`githooks/pre-commit` 只跑 `test_v6_smoke.py` + `validate`，二者只校验孪生内部自洽，不校验四者互相一致，分叉被长期掩盖。

## 一、三套数值真相互不一致（最严重）

同一参数存在三套数值且互不对上，游戏实际以 **Bake/JSON** 为准：

| 参数 | 权威文档 §7 | Constants/Params/孪生默认 | 烘焙预设（实际运行） |
|------|-------------|--------------------------|---------------------|
| CP (W) | 400 / 420 / 480 | 780（默认） | **889.7 / 1010.8 / 1029.8** |
| W′_max (J) | 20000 / 24000 / 28000 | 20000 | **21322 / 31038 / 31655** |
| sprint_cap (W) | 1450 / 1350 / 1500 | 2400 / **1200** | **2355 / 2724 / 2747** |
| W′ 恢复 | Skiba / 15 / 18 | 12 | **10.0 / 11.86 / 14.28** |
| energy_coeff | 未列 | 9.5e-7 / **3.5e-5** | **1.06e-7 ~ 1.70e-7** |

- 文档 §7 从未匹配任何仓库内烘焙版本（连 `.backup` 旧烘焙也对不上），属「理想锚点」。
- **`energy_to_stamina_coeff` 漂移 ~200–330×**：三档预设 ≈1e-7，`SCR_RSS_Params.c:16` 默认 = `3.5e-5`。选 Custom 档会触发两个数量级的消耗偏差。
- 证据：`SCR_RSS_SettingsPresetBake.c:67/118/144/195/221/272`；`SCR_RSS_Params.c:16/334/336/340`；`SCR_RSS_Constants.c:643-646`；`rss_digital_twin_fix.py:241/2038/2460-2463`。
